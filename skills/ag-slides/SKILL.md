One talk, one `slides.qmd`, three outputs: `<P>-pptx`, `<P>-beamer`, `<P>-revealjs`. The style lives with the project (its charter); this skill holds only the tools. Scripts are in `scripts/` and run with `uv run`.

## Where things live

| What | Where |
|---|---|
| Charter of project P | inside P, e.g. `projects_active/local_iris/charter/` (never in a folder shared with partners) |
| A talk | the project's local presentations folder, or `my_presentations_active/<YYYY>/<YYYYMMDD>_<event>/` from the `ag-workspace` template |
| Shared with partners | exported `.pptx` / `.pdf` only, copied after the user approves |

Nothing Claude-related (`.claude/`, notes, scripts) goes into a partner-shared folder.

## Charter (once per project)

```
charter/
  charter.yml          name, template, aliases, role -> layout, font fallbacks
  _brand.yml           Quarto brand: colours, fonts, logo (schema of the installed Quarto)
  <template>.pptx      the project's official template, unmodified
  build/               generated by `charter.py build`, never edited
    _extensions/<P>/   Quarto format extension: scss, beamer theme, filter, backgrounds
    reference-base.pptx
    layouts.pdf        every template layout, labelled
    geometry.yml       placeholder boxes in pt
```

```sh
uv run ~/.claude/skills/ag-slides/scripts/charter.py build <charter>
```

Build steps: aliases applied, PowerPoint renders each role's layout with placeholders removed (backgrounds), placeholder geometry and master text styles read from the template, Beamer theme and revealjs scss generated from geometry + `_brand.yml`.

Setting up a new charter:
1. Copy the official template. Read colours and fonts from the **master and layouts**, not `ppt/theme/theme1.xml`: templates often keep the stock Office theme and hardcode the charter (iRIS does).
2. Write `_brand.yml` from those values; check field names in `/Applications/quarto/share/schema/definitions.yml` (`brand-*` ids).
3. Build, open `build/layouts.pdf`, pick `layouts:` roles from the pictures. Layout names lie (iRIS "Blank-white" is green).
4. Pandoc needs layouts named `Title Slide, Title and Content, Section Header, Two Content, Comparison, Content with Caption, Blank`; alias missing ones in `charter.yml`.
5. Fonts only in Office (e.g. Arial Nova Cond) get `font_fallbacks` for LaTeX and browsers; the pptx keeps the real font.
6. A template that needs a lighter hand: `restyle:` in `charter.yml`, applied at build time to a copy of the template, so the official file stays as issued and all three formats follow. Per layout: `background` (palette name), `remove` (shape names), `width` or `box: {name: [x, y, w, h]}` (pt), `align: {name: l|ctr|r}`, `font: {name: {size, bold}}`, `color` (text, palette name; set even where the shape inherits its colour), `fade` (picture opacity, %), `add` (bars `{x, y, w, h, fill: [colour]}`, a two-colour top-to-bottom gradient, `radius` in pt for a rounded pill; or static text `{x, y, w, h, text, size, color}`). Footer boxes keep their alignment and colour in every format (geometry reads them). `master: {body_color: ...}` recolours the master body text. Shape names come from the layout; restyle every layout pandoc uses (Two Content, Comparison, Content with Caption too).
7. To choose a look, mock it up first: either PowerPoint renders of a template copy, or a claude.ai Slides style study (with partner material replaced by placeholders, and only after the user agrees to the upload). Then write the chosen look into `restyle:`, `_brand.yml` and `components.scss`. `_brand.yml` fonts with `source: google` load in revealjs (`@import` in the generated scss); the pptx keeps the template fonts and Beamer falls back through `font_fallbacks`.

## Deck

```sh
uv run ~/.claude/skills/ag-slides/scripts/charter.py deck <charter> <deck_dir>   # install/refresh extension, write _quarto.yml
quarto render slides.qmd                                                       # outputs in build/; pre-render writes _reference.pptx
```

Front matter:

```yaml
eyebrow: "..."                                   # optional label above the title
title: "..."
subtitle: "..."
author: "A. Ghribi"
institute: "GANIL"
footer: "A. Ghribi / <event>, <place>, <date>"   # fills pptx, beamer and revealjs footers
duration: 20                                    # minutes, for check_deck.py
format:
  <P>-pptx: default
  <P>-beamer: default
  <P>-revealjs: default
```

Every deck gets a "Contents" slide after the title, generated from the `#` and `##` headings by `charter.lua`: never write one by hand. `{.nocontents}` keeps a `##` slide off it; `{subtitle="..."}` on a `#` heading shows that line instead of the section's slide list. Slide roles: `#` section divider, `##` content, `## Title {.plain}` plain background. `## Title {logo="figures/logos/x.png"}` puts a project logo right of the title, in all three formats (box from the template geometry, `logo_box` in `charter.py`). When `charter.yml` names the template's logo shape (`mark: Picture 1`), the project logo takes that place and the template logo moves below it. One block per slide: a list or a table, never both, and no text after a table (pptx moves it to an extra slide). Tables: at most 4 columns, 7 rows, about 10 words per cell. Details that do not fit go in `::: {.notes}`. Two columns: `:::: {.columns}` with two `::: {.column}`. Speaker notes: `::: {.notes}`. Figures: files in `figures/` (draw.io sources next to the export); numbers on slides come from code or a cited source, never typed from memory.

Re-run `charter.py deck` after every charter rebuild.

Diagrams: `::: {.diagram src="figures/x.yml"}` and an empty closing `:::`. The spec format is in the `scripts/diagram.py` docstring (boxes, flows, text, images, steps with captions). `diagram.py` (pre-render, needs `rsvg-convert`) draws it: revealjs inline SVG with fragments and moving flows, beamer one overlay per step, pptx native shapes in groups that fade in on click. Steps stack, so a `clear:` or a full-canvas image swaps the picture. Icons: `icon="name"` on a card, a lucide name, fetched once into `_icons/`. Beamer has more pages than slides on diagram slides, so `compare.py` rows stop lining up after the first diagram.

## Components and animation

Every charter ships `components.scss` (colours from `$brand-*`) and the filter rules below. A slide with a bare list on a white body is the last resort: reach for a component first.

| Markup | revealjs | pptx, beamer |
|---|---|---|
| `::: {.lead}` one sentence `:::` | key message | paragraph |
| `::: {.tiles}` of `::: {.tile}` with `[160]{.num}` then a label | number tiles at the bottom of the slide | pptx: shapes; beamer: list, number in bold |
| `::: {.cards}` of `::: {.card}`, first paragraph = card title; `.card .accent` for the odd one | cards in a row | pptx: shapes; beamer: list, `**title**: text` |
| `::: {.steps .build}` of `::: {.step}` | numbered cards joined by arrows | pptx: shapes; beamer: list |
| `::: {.timeline months=50 now=1}` over `- M8 D2.1 Title` items (ids starting `MS` are milestones) | axis, deliverables above, milestones below, labels stacked so none overlap | two tables in columns |
| `[T2.3]{.tag}` | small pill | text |
| `[Source: ...]{.credit}` (no image on the slide) | small grey right line | paragraph |
| `![Source: ...](figures/x.png)` | caption as a small credit | caption (beamer: no "Figure n:") |

Rules:
- At most 4 tiles, cards or steps per slide (`check_deck.py` counts them); about 15 words per card. Timeline: at most 14 events, titles of 2 to 4 words; `label-up` and `label-down` set the label width in months when the defaults (months/4, months/6) collide.
- Animation, revealjs only: slides fade (`transition: fade`), tiles and cards rise in turn when their slide opens, the timeline axis draws itself and events appear in month order. `.build` turns children into fragments the speaker steps through: use it where the order is the message (a pipeline, a plan), not on every slide. `prefers-reduced-motion` turns entrance animations off.
- Content is centred vertically in the template body box.
- pptx shapes: pandoc leaves tiles, cards and steps as a list; `charter.lua` writes their content to `_components.json` and the post-render step `pptx_components.py` (wired by `charter.py deck`, which keeps a deck's own pre/post-render entries) replaces the list with shapes in the body box, and adds the eyebrow, smaller author lines and the institute on the title slide. Reruns change nothing.
- pptx keeps one image per column and drops text under an image: merge image pairs into one figure (PIL), put credits in the image caption, put text in the other column.
- `{auto-animate=true}` on two consecutive `##` headings morphs matching elements (same text or `data-id`) between them; use it when the second slide zooms into a part of the first.
- Screenshots and decktape: append `?fragments=false` to the URL to show every fragment (`compare.py` does).

## Links

Every link on a slide goes in the deck's `links.yml`, never in the slide text. `links.lua` and `pptx_links.py` draw it as a row of clickable links between body and footer, in all three formats. A deck without the file gets no strip. Keys are slide titles, `check_deck.py` flags a key that matches no slide.

```yaml
ESS - finding faults without labels:
  - [git, Team code, https://github.com/org/repo/tree/main/team]   # git icon: repo or folder
  - [data, Dataset, https://doi.org/...]                           # data icon: only where the data is public
  - [info, Challenge page, https://...]                            # (i): page with more information
  - [ref, "Author et al., PRAB 27 (2024)", https://doi.org/...]    # footnote style, no icon: paper, talk, Indico
```

Icons sit in `scripts/icons/` (lucide ISC, Simple Icons CC0); `charter.py build` renders them in the charter's secondary colour, so rebuild the charter once after updating the skill.

## Workflow

1. `read_me.md`, `abstract.md`, `PLAN.md` from the presentation template: key message, audience, slot, one line per slide with its message and evidence. Get the plan approved before writing slides.
2. Write `slides.qmd`. Text in the user's voice (`ag-voice`); claims sourced (`ag-rag` for the user's own documents).
3. Lint: `uv run scripts/check_deck.py slides.qmd` (exit 1 on any HIGH: placeholders, `[UNVERIFIED]`, missing figure or footer, slide count over the slot; density against the CAS 2026 limits).
4. Render, then `uv run scripts/compare.py <deck_dir>`: one row per format. Read the sheet; same slides, same order, nothing clipped or overlapping.
5. Exports to `exports/`; copy to the shared folder only after approval.

## Tools and pitfalls

- `scripts/pptx2pdf.sh in.pptx [out.pdf]`: PowerPoint export. It opens files with `open -a` because AppleScript `open` on a path outside PowerPoint's sandbox fails silently.
- revealjs PDF: `npx -y decktape@3 reveal --size 1600x900 --chrome-path "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" build/slides.html build/slides_reveal.pdf` (allowed by the rule `Bash(npx -y decktape@3 *)`). Headless Chrome `--print-to-pdf` prints one blank page.
- `metadata-files:` is pandoc's `--metadata-file`: it never carries `format:` options. House styles go through the format extension.
- revealjs output is `build/slides.html` plus `build/slides_files/` and `build/_extensions/<P>/backgrounds/` (copied by the deck's `resources:`). Move or share the whole `build/` folder. Quarto refuses chalkboard in self-contained output, so there is no single-file HTML.
- revealjs plugins on: menu, chalkboard (whiteboard theme, `c`/`b`), pointer (`q`, vendored from quarto-ext/pointer).
- revealjs backgrounds use `contain`, never `cover`: reveal letterboxes the 16:9 slide, and `cover` crops the template on 16:10 or 4:3 screens. Footer and slide number are drawn inside each slide by the filter (reveal's own sit at the window edges), with numbers written at build time (CSS counters skip the slides reveal hides).
- revealjs: `#` headings create vertical stacks, so `#/n` hashes skip slides; navigate by id. `hash-type: number` drops section ids and breaks `#title-slide` CSS.
- Beamer: pandoc emits the title page as frame 1 with `\titlepage`; the theme switches background and footline on frame 1.
- Partner pptx decks: edit with python-pptx on the template layouts, never restyle someone else's slides; merge their slides as they are.
- Keynote: open the pptx in Keynote. There is no Keynote source format.
- Claude Design HTML decks (`<deck-stage>`, PptxGenJS pptx) do not round-trip; rebuild their content in `slides.qmd`.
